# accounting-agent-printer

Агент принтеров для приложения **accounting**. Инвентаризирует установленные на машине
принтеры, считывает счётчик страниц за весь срок службы (SNMP — для сетевых принтеров;
PJL / счётчик спулера (WMI) / реестр — для локальных/USB, см.
[Источники счётчика страниц](#источники-счётчика-страниц)), отслеживает доступность
принтеров между циклами и отправляет JSON на сервер. Windows 7 SP1 и новее, работает как
служба без участия пользователя.

Агент построен на [accounting-agent-core](https://github.com/kirillketrik/accounting-agent-core):
служба, `agent.ini`, лог, расписание, отправка на `/api/agent-ingest`, WebSocket-канал,
GUI-установщик, настройки профиля с сервера и команды установки описаны в README ядра.
Здесь только то, что относится к принтерам. Агент опознаётся сервером по **hostname и IP**
(они в корне каждого отчёта).

## Установка

Скачайте `accounting-agent-printer-setup.exe` со страницы
[Releases](https://github.com/kirillketrik/accounting-agent-printer/releases) и запустите:
мастер спросит адрес сервера, ключ профиля, номер профиля и интервал отчётов. Тихая установка:

```powershell
accounting-agent-printer-setup.exe /silent /url=https://srv/api/agent-ingest /key=<ключ> /profile=1 /interval=60
```

Остальные параметры (`/wsurl`, `/dir`, `/nows`, удаление), логи и WebSocket — в README ядра.

## Сборка

Нужны MSVC (Visual Studio 2022 Build Tools, «Разработка классических приложений на C++»),
CMake 3.20+ и репозиторий ядра: `..\accounting-agent-core` (рядом), либо
`-DACCOUNTING_AGENT_CORE_DIR=<путь>`, либо FetchContent
(`-DACCOUNTING_AGENT_CORE_TAG=<тег>` закрепляет версию ядра).

```powershell
scripts\build.bat Release                  # core из ..\accounting-agent-core
scripts\build.bat Release D:\src\core      # core из указанной папки
```

`build.bat` сам находит `cmake`/`ninja` (PATH → CLion → Visual Studio). Результат в
`cmake-build-release\`: `printer_agent.exe`, **`printer_setup.exe`** (GUI-установщик, один файл),
`agent.ini` и скрипты службы. В CLion: открыть проект, профиль с тулчейном MSVC и генератором
Ninja, запускаемая цель — `printer_agent`.

Локальная копия конфигурации с настоящим ключом: `config\printer.ini` (в git не попадает,
подставляется в `agent.ini` при сборке; иначе берётся `config\printer.ini.example`).

Установка и запуск (мастер установщика, `/silent`, `--console/--install`), WebSocket,
настройки с сервера и просмотр логов — в README ядра.

## Подключение к серверу

На сервере создайте профиль агента, скопируйте ключ (показывается один раз) в
`[server] auth_token`, номер профиля — в `profile_id`, адрес `…/api/agent-ingest` — в `url`.
Профиль принтеров (в отчёте список `printers`, серийного номера нет, актив ищется по названию и порту):

| Настройка профиля | Значение |
| --- | --- |
| Путь к списку записей | `printers` |
| Как найти актив | сочетание `name` + `portName` (пробелы по краям не важны); новая запись попадает во «Входящие», актив выбирается один раз вручную |
| Действие | показание счётчика «Страницы», путь `pageCount` |
| Время измерения | `collectedAtUtc` (есть и в каждой записи, и в корне отчёта) |

## Конфигурация принтерного агента

Общие секции `[server] [polling] [websocket] [logging]` — в README ядра. Секции этого агента
(полный пример — `config\printer.ini.example`):

| Секция | Ключ | Значение |
|---|---|---|
| `[polling]` | `offline_after_consecutive_failures` | Принтер помечается `"offline"` только после стольких неудачных циклов подряд (по умолчанию 3). |
| `[snmp]` | `community`, `port` | SNMP v1 community (по умолчанию `public`) и UDP-порт 161. |
| | `timeout_ms`, `retries`, `retry_delay_ms` | Таймаут одной попытки, всего попыток на OID, задержка между ними. |
| `[discovery]` | `enabled` и др. | Опциональный SNMP-поиск принтеров в локальных подсетях. |
| `[pjl]` | `enabled`, `timeout_ms` | **Выключено по умолчанию.** PJL-запрос счётчика для локальных/USB принтеров — перед включением см. [Источники счётчика страниц](#источники-счётчика-страниц). |

## Как это работает

На каждом цикле сбора данных агент:

1. Перечисляет установленные принтеры через WMI (`Win32_Printer`), пропуская
   виртуальные принтеры (Microsoft Print to PDF, XPS, OneNote, Fax,
   перенаправленные/сессионные принтеры и т. п.).
2. Классифицирует порт каждого принтера: **TCP/IP** (`Win32_TCPIPPrinterPort`),
   **WSD** (хост/IP извлекаются из поля `Location` в WMI, включая IPv6
   link-local-адреса с zone id), **Local/USB** (`USB*`/`COM*`/`LPT*`) или
   **Other**.
3. Считывает счётчик страниц за весь срок службы:
   - Для принтеров TCP/IP и WSD — самостоятельно реализованный **SNMP v1 GET**
     поверх WinSock2 к OID `prtMarkerLifeCount`
     (`1.3.6.1.2.1.43.10.2.1.4.1.1`), с повторными попытками и поддержкой
     IPv4/IPv6.
   - Для локальных/USB принтеров — эвристическое сканирование ветки реестра
     `HKLM\SYSTEM\CurrentControlSet\Control\Print\Printers\<name>\PrinterDriverData`
     в поисках значения счётчика, специфичного для производителя. Это
     неструктурированные данные конкретного вендора, поэтому это эвристика, а
     не гарантия.
4. Определяет собственные IP-адреса хоста.
5. Отправляет всё как один JSON-документ через HTTP(S) POST (WinHTTP) на
   `…/api/agent-ingest` сервера с заголовком `Authorization: Bearer <ключ профиля>`.
   Что сделать с отчётом (найти актив, записать показание), решает профиль агента
   на сервере.

Один нерабочий принтер, недоступная по SNMP цель или неудачный HTTP POST
никогда не приводят к падению агента и не прерывают остальной цикл — что
именно значит "по возможности" на практике, см. в разделе
[Известные ограничения](#известные-ограничения).

## Данные отчёта

Один JSON-объект на цикл сбора, отправляется как `application/json`:

```jsonc
{
  "hostname": "PRINT-SRV01",
  "collectedAtUtc": "2026-08-25T13:50:12.345Z",
  "hostIpAddresses": [
    { "ip": "10.0.1.15", "isIPv6": false, "adapter": "Ethernet" }
  ],
  "printers": [
    {
      "name": "Kyocera ECOSYS M2235dn",
      "driverName": "Kyocera ECOSYS M2235dn KX",
      "portName": "IP_10.0.1.42",
      "portType": "TCP/IP",           // "TCP/IP" | "WSD" | "Local/USB" | "Other"
      "location": "3rd floor",
      "shared": false,
      "shareName": "",
      "network": true,
      "workOffline": false,
      "printerStatus": 3,
      "resolvedHost": "10.0.1.42",    // null, если неприменимо/не резолвится
      "isIPv6": false,                // присутствует, только если resolvedHost не null
      "pageCount": 48213,             // null, если неизвестен
      "pageCountSource": "snmp",      // "none" | "snmp" | "registry:PrinterDriverData" | "wmi:PrintQueue.TotalPagesPrinted" | "pjl:INFO_PAGECOUNT"
      "snmpAttempted": true,
      "snmpReachable": true,
      "snmpSysDescr": "KYOCERA ECOSYS M2235dn",  // отсутствует, если пусто
      "status": "online",             // "online" | "offline" | "unknown" — см. ниже
      "consecutiveFailures": 0,
      "note": ""                                  // отсутствует, если пусто
    }
  ],
  "removedPrinters": [
    // присутствует (возможно, пустым) в каждом цикле; по одной записи на
    // принтер, который встречался в предыдущем цикле, но больше не установлен
    // в Windows вообще (не просто недоступен — реально удалён)
    { "dedupKey": "10.0.1.42", "name": "Kyocera ECOSYS M2235dn" }
  ]
}
```

Серверу эту схему описывать не нужно: путь к списку (`printers`), поле для
поиска актива (`name`) и поле показания (`pageCount`) задаются в профиле
агента — см. [Подключение к серверу](#подключение-к-серверу).

## Источники счётчика страниц

Для сетевых принтеров (TCP/IP, WSD) агент сначала пробует стандартный OID
SNMP `prtMarkerLifeCount` по обычному индексу таблицы, а для устройств, где
счётчик(и) индексируются иначе (например, по цветовым плашкам), переходит к
обходу всей таблицы через GETNEXT.

Для локальных/USB принтеров — в порядке приоритета:

1. **PJL-запрос статуса** (`pjl:INFO_PAGECOUNT`) — опционально, см. `[pjl]`
   выше. Отправляет крошечную сырую PJL-команду напрямую на устройство и
   читает его собственный ответ, поэтому отражает истинный счётчик страниц за
   весь срок службы из прошивки/NVRAM самого принтера — единственный из
   здешних источников, переживающий перезапуск службы диспетчера очереди
   печати или переустановку драйвера. **Работает через отправку настоящего
   задания на печать.** Принтер, не понимающий PJL, может в ответ напечатать
   искажённую или пустую страницу вместо того, чтобы молча проигнорировать
   команду, поэтому по умолчанию это выключено: включайте только после
   тестового цикла и физической проверки, что ваш принтер обрабатывает это
   безопасно.
2. **Счётчик диспетчера очереди печати через WMI**
   (`wmi:PrintQueue.TotalPagesPrinted`) — работает для любой локальной
   очереди без содействия со стороны производителя, но сбрасывается в 0 при
   каждом перезапуске службы диспетчера очереди печати, так что это
   "страниц с последнего запуска диспетчера", а не счётчик за весь срок
   службы.
3. **Эвристика по реестру** (`registry:PrinterDriverData`) — специфична для
   производителя и недокументирована; используется, только если два
   источника выше ничего не нашли.

## Статус принтера и обнаружение удалённых принтеров

Поле `status` каждого принтера в отчёте отражает доступность *за несколько
циклов подряд*, а не только за текущий — единичный таймаут SNMP или
кратковременно недоступная USB-очередь сами по себе не переключают его в
`"offline"`. Переключение происходит только после
`offline_after_consecutive_failures` (по умолчанию 3) неудачных циклов
подряд; любой один успешный цикл сбрасывает счётчик и сразу возвращает
`"online"`. `"unknown"` означает, что для типа порта принтера вообще нет
проверки доступности (`PortType::Other`) — такой принтер никак не участвует
в определении offline-статуса. Это состояние сбрасывается при каждом
перезапуске процесса агента (перезапуск службы, перезагрузка машины) — оно
не сохраняется на диск.

Если принтер полностью исчезает из собственного списка принтеров Windows
между одним циклом и следующим (удалён, а не просто недоступен), он
перестаёт появляться в `printers` и вместо этого один раз попадает в
`removedPrinters` в том цикле — у сервера уже есть вся остальная информация
об этом принтере из его последнего обычного отчёта.

## Известные ограничения

- **Счётчики страниц локальных/USB принтеров работают «по возможности».** Содержимое
  `PrinterDriverData` в реестре специфично для производителя; агент берёт первое значение,
  чьё имя похоже на счётчик. Оно может быть неверным или отсутствовать.
- **Только SNMP v1**, без шифрования/аутентификации, кроме community string.
- Один и тот же физический принтер, установленный дважды (WSD и TCP/IP), создаёт две записи
  в отчёте; дедупликация — на стороне сервера.
- Если счётчик неизвестен, `pageCount` в отчёте — `null`.

## Структура проекта

```
CMakeLists.txt            add_accounting_agent(ID printer ...) + подключение ядра
src/
  printer_agent.cpp       класс PrinterAgent + GetAgentInfo()/CreateAgent()
  printer_config.*        секции snmp/pjl/discovery
  collector/              перечисление Win32_Printer, оркестрация цикла, статус online/offline
  snmp/                   самостоятельно реализованный SNMP v1 (ASN.1 BER + WinSock2)
  registry/               эвристика по PrinterDriverData
  pjl/                    PJL-запрос счётчика
  discovery/              SNMP-поиск принтеров в подсетях
  model/                  PrinterInfo
config/printer.ini.example
scripts/build.bat
```
